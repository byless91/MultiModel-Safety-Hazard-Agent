# 最终改造计划：在原项目上增量完善

版本：1.0；日期：2026-10-29。本文是后续唯一实施入口。R0–R8 记录保留为历史基线；Claude 原方案、交接原稿及未完成实现已纳入清理前备份，不再按原阶段清单顺推。

## 1. 最终目标

保留现有 Vue/FastAPI 项目，把它逐步完善为“巡查录入、人工复核、位置统计、知识查询”平台。管理者与巡查员使用同一个系统的不同入口，沿用 admin/reviewer/inspector 角色。

核心链路：拍照和描述 → AI 提供分类及依据建议 → 人工补全并确认类别/等级 → 保存可追溯记录 → 管理页查看已确认数据 → 原整改与复检闭环。

沿用一级高风险、三级低风险的既有语义。AI 建议与人工最终结论分开保存，模型失败或资料不足明确展示，不能伪装为已确认。

## 2. 保留与收敛

| 能力 | 处理方式 |
|---|---|
| 登录、角色、图片上传、幂等、后台任务和刷新恢复 | 继续复用现有实现 |
| Provider、知识检索、证据引用、人工修订/审计 | 增量适配，保持一个权威入口 |
| 首页、历史、详情、知识库、整改和 Markdown 导出 | 在原页面扩展，旧记录保持可读 |
| 快速分类 | 复用模型调用及检索基础，明确新的轻量处理模式 |
| 位置与统计 | 增量字段及一个管理统计页，按实际需求新增小模块 |
| 案例查询 | 先复用知识库与已确认历史记录，不先建第二套案例系统 |

首版范围外：预测、自动资源调度、独立双应用、预聚合表、Redis、PostGIS、多个地图引擎、PDF/Word 双报告体系和强制图片压缩。真实需求与测量结果出现后再单独立项。

## 4. 实施边界

1. 先明确请求/响应、字段含义和状态，再同时实现前后端；继续使用现有 `/api/v1` 认证体系。模块可按职责拆分，但业务规则与状态只维护一份。
2. 巡查员录入并补全信息，复核员/管理员沿用原审核权限；审核后进入正式统计。新需求如改变角色权限，必须明确更新合同与权限回归。
3. 所有新字段通过提交到仓库的增量 Alembic 迁移进入数据库。部署只执行已审阅的升级，不现场自动生成迁移，不删除历史审计或批量重算人工结果。
4. 分类体系先覆盖少量可解释类别，建立小型人工核对集。用同样资料对比单模型与双模型，按实测收益决定调用策略。
5. 位置允许缺失并标明精度；自动地理编码是增强项。只有真实持久化和前后端均验证后，才能标记地图功能完成。
6. 统计默认使用人工已确认记录。公开报道数量展示为“收集到的案例数”；缺少巡查覆盖量等分母时，不据此宣称某区更危险，也不包装成预测。
7. 先用少量可手算数据检验统计正确，再扩大演示数据。条数不是业务验收标准；模拟数据必须显式标识。
8. 保持单实例、单 worker 与 SQLite/PG 现有支持边界。新增依赖必须写入正式 manifest 和锁文件。

## 5. 每阶段的完成标准

- 每次只完成一个可运行的小改动，立即验证；新增或修改的测试统一放在根目录 `test/`。
- 保留旧测试与历史评测结果，离线回归使用独立测试数据库/目录，真实模型质量单独验证。
- 通过相关聚焦测试后跑必要回归；页面成功提示必须对应已保存的数据和可查询状态。
- 每处较大改动验证后提交、推送，并展示提交名称与实测结果。
- 完成一阶段后只更新本计划状态、README/架构中受影响的说明，不再新增多份“完成清单”。
