# 最终改造计划：知识库与分类助手 + 行业数据平台

版本：2.0；日期：2026-10-29。根据用户确定的两个方向合并更新。本文是后续唯一实施入口，继续在原 Vue/FastAPI 项目上增量改造。R0–R8 保留为历史基线；M0 清理结果继续有效，尚未实施的阶段按本版本执行。

## 1. 最终目标

将项目完善为“安全隐患知识与数据平台”，让两条业务主线共用一套记录、知识、审核和权限体系：

- **知识库与分类助手**：拍照/描述 → AI 建议类别与通用标签 → 检索相关条款 → 人工确认落库。知识库按消防、生产、社区、林区组织，支持来源、版本、适用范围和更新提醒。
- **行业数据分析**：经确认的记录 → 地理与时间聚合 → 分布地图、历史趋势、同类设施/场景对标 → 展示可追溯整改案例，辅助安排后续巡查。

两者形成闭环：知识帮助规范录入，录入沉淀可比较数据，分析结果和已验证整改经验再反馈给巡查员。管理者与巡查员使用同一个系统的不同入口，沿用 admin/reviewer/inspector 角色。

新主流程以分类和证据查询为中心，**不让 AI 自动判定等级或一键生成具有规范效力的结论**。风险等级可由人工选填；未填写时显示“未分级”，不得默认中风险。历史记录仍沿用一级高、三级低的既有语义。模型失败、无法分类或证据不足必须明确展示。

## 2. 保留与收敛

| 能力 | 处理方式 |
|---|---|
| 登录、角色、图片上传、幂等、后台任务和刷新恢复 | 继续复用现有实现 |
| Provider、知识检索、证据引用、人工修订/审计 | 扩展为标签建议、条款检索与版本追溯，保持一个权威入口 |
| 首页、历史、详情、知识库、整改和 Markdown 导出 | 在原页面扩展，旧记录保持可读 |
| 分类标签 | 分开保存 AI 建议和人工最终标签，维护分类体系版本；不把置信度当作真实准确率 |
| 多行业知识库 | 在现有文档/条款检索上增加行业、版本及审核状态；逐库核验内容 |
| 位置与统计 | 增量字段及一个管理统计页；记录数、隐患项数和标签数分别定义 |
| 同类整改案例 | 复用知识库与已确认历史/整改记录，按设施、类别和场景检索，不先建第二套案例系统 |

首版完成分类录入、知识版本、来源位置、描述性统计及案例对标。法规更新监测、趋势预警和部署验证安排在后续阶段，具体范围见下表。独立双应用、预聚合表、Redis、PostGIS、多个地图引擎、PDF/Word 双报告体系和强制图片压缩不作为当前必做项。

## 4. 实施边界

1. 先明确请求/响应、字段含义和状态，再同时实现前后端；继续使用现有 `/api/v1` 认证体系。模块可按职责拆分，但业务规则与状态只维护一份。
2. 巡查员录入并补全分类/标签，复核员/管理员沿用原审核权限；审核后进入正式统计。风险等级是可选人工字段，不是模型分类结果的必填代理。新需求如改变角色权限，必须明确更新合同与权限回归。
3. 所有新字段通过提交到仓库的增量 Alembic 迁移进入数据库。部署只执行已审阅的升级，不现场自动生成迁移，不删除历史审计或批量重算人工结果。
4. 分类体系先覆盖少量可解释类别及标签，记录体系版本，建立人工核对集。用同样资料对比单模型与双模型，按实测收益决定调用策略。法规引用记录来源、版本、条款和适用范围；相似度不作为适用性判定。
5. 位置允许缺失并标明精度；自动地理编码是增强项。只有真实持久化和前后端均验证后，才能标记地图功能完成。
6. 统计默认使用人工已确认记录，明确地域、时间、行业、设施和统计单位。公开报道数量展示为“收集到的案例数”；缺少巡查覆盖量、设施数量等分母时，不把数量排名解释为风险排名。对标优先展示同类整改经验，不直接给出自动处置决定。
7. 先用少量可手算数据检验统计正确，再扩大演示数据。条数不是业务验收标准；模拟数据必须显式标识。
8. 保持单实例、单 worker 与 SQLite/PG 现有支持边界。新增依赖必须写入正式 manifest 和锁文件。
9. 趋势预警先做可解释规则提示；设施老化分析需要安装/维护记录，季节性分析需要足够历史覆盖。预测模型须另有独立历史回测和提前登记的验收目标，不能用平滑折线代替预测。
10. 首版按单组织部署；多地区/多部门数据汇聚须有授权、脱敏、来源标记和访问控制。SaaS 多租户隔离、跨组织共享和计费需要单独设计验证，现有角色权限不能直接当作组织隔离。
11. 离线交付先验收本地知识查询、人工录入和已有记录访问。离线 AI 分类需要另行接入并验证本地模型；无 Key 时的 Mock 只用于演示，不能当作离线智能能力。

## 5. 每阶段的完成标准

- 每次只完成一个可运行的小改动，立即验证；新增或修改的测试统一放在根目录 `test/`。
- 保留旧测试与历史评测结果，离线回归使用独立测试数据库/目录，真实模型质量单独验证。
- 通过相关聚焦测试后跑必要回归；页面成功提示必须对应已保存的数据和可查询状态。
- 每处较大改动验证后提交、推送，并展示提交名称与实测结果。
- 完成一阶段后只更新本计划状态、README/架构中受影响的说明，不再新增多份“完成清单”。

## 6. 价值验证与商业目标

- **内部工具路线**：验证是否减少巡查员查法规、整理记录和复核返工的时间。图片中的“效率提升 30–50%”作为待验证目标，用同任务人工方式/单模型/本系统对照测量，未实测前不写成成果。
- **行业数据路线**：验证分布、趋势及类似设施整改案例是否帮助管理者定位待复查对象。分别检查数据覆盖、类别/标签正确性、去重、区划/日期正确性和可比性，地图展示本身不代表决策有效。
- **部署与商业探索**：政府/企业内部工具、按城市/行业提供服务列为潜在交付方式；在真实用户、授权数据和组织隔离就绪后验证。面向保险的风险评分、承保/定价数据服务属于进一步研究，不纳入首版成果或可靠性承诺。
