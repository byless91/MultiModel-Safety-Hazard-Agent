# R2 检索降级与逐项证据

## T05：向量空间与恢复（2026-10-28 完成）

- 查询失败后将语料和查询同时切换至 `hash:sha256-v1:256`，不再按维度是否为 256 猜测空间。
- hash 与 provider embedding 缓存分开，失败查询不覆盖真实缓存；缓存批次数、维度、有限值经过校验才保存。
- 默认 60 秒后允许下一次查询探测恢复，`EMBEDDING_RECOVERY_SECONDS` 可配置。查询与语料候选均校验通过后才切换；失败保留原 hash 索引。
- 索引元信息使用格式版本 2，包含 embedding_space；旧格式或形状不一致的索引使用 embedding 缓存重建，不要求重新向量化未变化语料。
- 重建和查询继续共享 RLock，候选索引构建完成后才发布；加载失败回滚全部语料/索引属性，避免查询读到半成品。
- 检索结果和证据保留 `embedding_space`、`embedding_fallback`；降级和恢复均有日志。本轮不把 hash 分数当成真实语义质量验证结果。
- 测试：`test/backend/test_rag_embedding_recovery.py`，22 passed，实际覆盖 NumPy 和已安装的 FAISS。
- 回归：根目录 99 passed；历史 334 passed、1 个 R1 保留的 strict xfailed；Ruff 通过。

聚焦覆盖：查询超时（2 维和 256 维 provider）、冷却期间不重复请求、缓存恢复、失败探测保留索引、非法批次/NaN 不污染缓存、重启复用真实缓存、provider 维度变化、重建失败回滚和并发读取。
