# R3 验证记录（2026-10-28）

## T07：任务恢复与迟到回写

- 任务记录 worker 身份、执行代次和租约；默认 30 秒租约、最多每 5 秒续租和清扫。未升级的 running 兼容原超时规则，启动取得独占锁后立即终止所有遗留 running。
- 排队任务不因等待时间长而失败；归属不明的调用不自动重放，避免重复费用。
- 进度、成功、失败均校验执行代次及有效租约；job 与结果写入同一事务。失败保留原结论及复核信息，已确认记录不会被覆盖。
- SQLite checkpoint 使用本地 OS 独占锁；线程未退出时继续持锁。它不提供多副本或分布式 worker 支持。
- 每次启动创建新的 asyncio Event，修复 TestClient/多次 lifespan 的跨事件循环复用。
- 新增可重入 Alembic 租约列迁移，覆盖旧表存量数据升级。
- 聚焦：`python -m pytest test/backend/test_job_recovery.py -q`：13 通过（SQLite、Mock、可控时钟）。覆盖快速重启、运行时清扫、20 分钟健康续租、迟到成功/失败、新代次隔离、复核信息保留、独占锁、跨循环重启及迁移。

## T08：原子入队与认领

- assessment、幂等键、图片元数据、初始 job 在同一事务提交，提交后才唤醒 worker。入队、提交或文件写入失败时整体回滚，只清理本次请求写入的文件和空目录。
- 认领使用单条 `UPDATE ... WHERE status='queued' ... RETURNING`，返回行才代表认领成功；PG 并发竞争未取得行时下个轮询重试。
- 同 key 的正常重放与并发冲突重放共用 202/job 语义。
- Docker 显式 `--workers 1`；README 修正“PG 即可多副本”的错误说明，说明本地 checkpoint、文件和索引限制。
- SQLite 聚焦及 T07 回归：19 通过、2 项 PG 条件测试跳过。
- 真实 PostgreSQL 16（本机临时容器 `postgres:16-alpine`、独立 `test_r3` 数据库）：T08 8 项通过，包含 SQLite/PG 并发认领对照，以及 PG 上三种故障回滚、提交后唤醒和幂等重放。每次单任务认领竞争重复 10 次，另测 4 个竞争者排空 20 个任务，无重复认领。
