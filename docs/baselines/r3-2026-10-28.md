# R3 验证记录（2026-10-28）

## T07：任务恢复与迟到回写

- 任务记录 worker 身份、执行代次和租约；默认 30 秒租约、最多每 5 秒续租和清扫。未升级的 running 兼容原超时规则，启动取得独占锁后立即终止所有遗留 running。
- 排队任务不因等待时间长而失败；归属不明的调用不自动重放，避免重复费用。
- 进度、成功、失败均校验执行代次及有效租约；job 与结果写入同一事务。失败保留原结论及复核信息，已确认记录不会被覆盖。
- SQLite checkpoint 使用本地 OS 独占锁；线程未退出时继续持锁。它不提供多副本或分布式 worker 支持。
- 每次启动创建新的 asyncio Event，修复 TestClient/多次 lifespan 的跨事件循环复用。
- 新增可重入 Alembic 租约列迁移，覆盖旧表存量数据升级。
- 聚焦：`python -m pytest test/backend/test_job_recovery.py -q`：13 通过（SQLite、Mock、可控时钟）。覆盖快速重启、运行时清扫、20 分钟健康续租、迟到成功/失败、新代次隔离、复核信息保留、独占锁、跨循环重启及迁移。

## T08：原子入队与认领

- assessment、幂等键、图片元数据、初始 job 在同一事务提交，提交后才唤醒 worker。入队、提交或文件写入失败时整体回滚，只清理本次请求写入的文件和空目录。
- 认领使用单条 `UPDATE ... WHERE status='queued' ... RETURNING`，返回行才代表认领成功；PG 并发竞争未取得行时下个轮询重试。
- 同 key 的正常重放与并发冲突重放共用 202/job 语义。
- Docker 显式 `--workers 1`；README 修正“PG 即可多副本”的错误说明，说明本地 checkpoint、文件和索引限制。
- SQLite 聚焦及 T07 回归：19 通过、2 项 PG 条件测试跳过。
- 真实 PostgreSQL 16（本机临时容器 `postgres:16-alpine`、独立 `test_r3` 数据库）：T08 8 项通过，包含 SQLite/PG 并发认领对照，以及 PG 上三种故障回滚、提交后唤醒和幂等重放。每次单任务认领竞争重复 10 次，另测 4 个竞争者排空 20 个任务，无重复认领。
- 命令：`python -m pytest test/backend/test_job_claiming.py test/backend/test_job_enqueue_atomicity.py -q`；PG 通过显式 `R3_TEST_POSTGRES_URL` / `TEST_DATABASE_URL` 指向本机测试库，未读取业务数据库。

## T09：追问预留与模型文本校验

- 新增可重入迁移，为 assessment 增加 `followup_token`。接受请求时通过条件 UPDATE 同时检查 needs_more_info、未确认、无活动 job、无预留和剩余额度；预留计数并转为 pending。异步追问 job 与预留一起提交，同步追问在调用模型前提交预留。
- 重复请求明确返回 409；额度耗尽返回 400。成功按预留标识提交结果，不再二次计数；模型异常、结果持久化异常、异步超时/重启清扫按对应标识释放一次额度，保留原结论、报告和复核内容，恢复等待补充信息。明确的新请求创建新的尝试，不自动重放失败调用；升级前无预留的 queued 追问保留完成计次兼容路径。
- `require_model_text` 统一输入策略。创建表单的 followup_answer、追问 answer、整改提交/确认 note、存量整改说明和追问原描述均校验；worker 在模型调用前再次校验 description、answer、OCR 列表及元素。恢复默认 2000 字限制；知识文件显式保留原来的独立长度策略。
- 修复异步创建时丢弃 followup_answer：持久化到 job.answer 并传给工作流。
- 单实例启动时另行回收“有预留、没有活动 job”的同步遗留请求；不触碰 queued/running 异步追问。同步进程硬崩溃后重启也可恢复等待补充信息，旧请求写回继续受预留标识保护。
- 聚焦文件：`test/backend/test_followup_reservations.py`、`test/backend/test_model_input_validation.py`，共 44 通过。包含五个并发请求、最后一个额度、成功不重复计数、失败/持久化失败释放、清扫幂等、旧请求不释放新额度、同步重启回收及异步预留保留、入队回滚、sync/async 注入/超长/空输入及存量数据旁路。
- 收尾扩展 T07 故障测试：asyncio Task 被取消后，真实模型线程仍可能运行。由真实线程的 finally 释放 OS 锁，避免异步完成回调提前释放；runner 重启清空旧活动对象。任务恢复最终 14 项通过，涵盖超时停止、取消、迟到结果和再次启动/停止。
