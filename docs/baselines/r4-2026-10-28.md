# R4 验证记录（2026-10-28）

## T10：统一真实 HTTP 并发入口

- 所有 OpenAI-compatible Provider 的 HTTP 请求共享同一进程级 gate；单模型直调、双模型分析、文本细化、整改比对和每批 embedding 均受控。Mock 不请求 HTTP，不占名额。
- 并发默认 4，必须为正数；等待名额默认最多 60 秒，可由 `LLM_QUEUE_TIMEOUT_SECONDS` 配置。排队超时抛出 ModelCapacityError（兼容 ModelUnavailableError），记录 capacity_timeout，无 HTTP、无内部排队重试。
- 每个实际 HTTP 尝试独立获取/释放名额；退避、JSON 解析、台账写入均在 gate 外。异常必经 finally 释放；递归 HTTP 入口明确拒绝，防止嵌套等待。
- 双模型共享线程池只负责任务调度，不在父线程持有 HTTP 名额，不再将线程池大小误称为所有模型并发上限。
- 聚焦：`python -m pytest test/backend/test_llm_concurrency_limit.py -q`，17 passed。使用 httpx.MockTransport 统计真实入口活动数，覆盖 6 请求/4 名额、单/双模型、用途混合、embedding 分批、6 类失败释放、429/503/超时重试、退避让出名额、排队超时及配置校验。

此处“实际 HTTP”指 Provider 的 HTTP 调用边界；测试 transport 为内存假服务，未访问真实模型，未消耗付费额度。

## T11：后端提交恢复合同

- 新增 nullable request_hash 及可重入 Alembic 迁移。初始描述、补充回答、解析后的 OCR、文件顺序、规范文件名和文件内容 SHA-256 一起生成不可变指纹；声明 MIME 不影响同一图片内容的身份。
- 重放时先读取并规范化请求，再校验指纹；不同内容返回 409 和原记录入口。历史无指纹 key 不猜测原提交，POST 返回 409，仍可只读查询。并发唯一键冲突整体回滚后再次验证指纹。
- 新增鉴权范围内 `GET /api/v1/assessment-submissions/{key}`，无模型调用、无状态写入，不受重放 TTL 或新请求预算拦截；缺失记录返回 404，悬空映射返回 410，不隐式重新执行。
- POST 保留终态 key 的原 TTL 合同；pending/failed 不会因 TTL 过期变成自动重跑。前端重试必须先 GET 查询，因此不会无意识进入过期终态 key 的新建路径。新建提交应使用新 key。
- 接受、重放及同步 502 返回 Assessment-Id / Location，CORS 显式暴露恢复响应头。重放初始 create job 的 queued/running 为 202，其余为当前 Assessment 200，不受当前 workflow_mode 或后续 followup job 干扰；查询结果 no-store。
- 聚焦：`test/backend/test_idempotent_recovery.py` 19 项；联同 T08 原子性测试共 23 passed。覆盖响应丢失、同步执行中查询、失败后重试、内容冲突、实际并发首次创建、旧 key、跨模式、后续追问与存量迁移。

补充真实 PostgreSQL 存量表迁移用例：在独立 schema 创建旧表及旧 key 后增列，再次迁移幂等，旧 key 及 nullable 指纹保留。默认 SQLite 运行时此 PG 条件用例跳过，PG 矩阵已实际运行。

## T11：前端提交与恢复

- 新提交使用加密随机 key；同次请求的原描述和 File 数组快照留在内存。结果不确定时禁止直接覆盖这次提交，用户必须查询、重试原内容或明确点击“新建研判”。
- 原内容重试先 GET 原提交；找到记录直接恢复，404 才以同一 key 重发同一内存快照；查询网络异常、401/403 等不会盲目 POST 或清除恢复标识。后端幂等校验处理并发重试的竞态。
- sessionStorage 仅保存 key、assessmentId、phase；不写描述、文件名或图片。刷新后即使原照片已不在内存，仍可查询。存储不可用时保持内存恢复能力。
- 同步 pending 不伪装完成；同步失败响应、异步轮询失败保留记录 ID。明确失败仅提供查询/记录入口，重新执行需要新建。完成后清除持久恢复标识，下一次提交使用新 key。
- 首页提供查询、原内容重试、记录/历史入口，并明确新建不取消已受理请求。补齐前端 AssessmentStatus 中遗漏的 failed 类型。
- 聚焦：`test/frontend/assessment-idempotency.spec.ts` 24 passed，覆盖新 key、同 key/原快照重试、查询丢失、同步失败、pending、异步轮询失败、刷新、双击、校验拒绝、鉴权失败、存储禁用及首页按钮交互。
