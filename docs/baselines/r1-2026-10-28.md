## T04：审计与有效结论

2026-10-28 完成。

- 使用现有 `human_review_json.history` 追加事件，包含事件 ID、认证身份、意见、时间、修改前后值；最新 resolution 保留原 API 兼容性。
- 第一次复核保存 AI 原始类别、等级、结论、报告和风险计算快照，后续复核不覆盖。旧 resolution 转为带 legacy 标记的历史；无法恢复的原 AI 信息明确标为 unavailable。
- 拒绝需要非空意见；edits 只允许类别、1–3 整数等级、非空结论，限制长度并拒绝未知字段。认证用户身份优先，客户端提供的 reviewer 不可伪造 JWT 审计身份。
- 相同批准或拒绝只读重放。条件更新同时检查旧审计内容、状态和活动任务，过时的并发写入返回 409，不丢失先提交的历史。
- 人工修改同步报告摘要、类别、等级、简报和工单期限；详情、列表、导出读取同一有效结果。改变类别时不沿用旧类别的专用处置建议。
- 原始 AI 风险计算和法规证据不重算、不改写，报告明确说明适用边界。后续完整的前端批准/拒绝/编辑界面仍属于 R7/T18。
- 旧人工修订记录生成只读兼容视图，不批量重写历史；审计 JSON 损坏时拒绝覆盖。
- 未增加持久化字段，因此无需 Alembic 迁移；已有库的确认记录兼容通过 API 回归验证。
