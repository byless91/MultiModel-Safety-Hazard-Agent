# 安全隐患智能知识库与决策平台 - 改造实施方案

**版本**: v1.0  
**创建日期**: 2026-10-29  
**实施周期**: 2 周（竞赛版）  
**仓库地址**: https://github.com/byless91/MultiModel-Safety-Hazard-Agent.git

---

## 📋 改造目标

将现有的 **AI 自动研判系统** 改造为 **双端智能决策平台**：
- **巡查员端**：快速录入 + AI 分类建议 + 法规推荐
- **管理者端**：热力图 + 对标分析 + 趋势预测

---

## 🎯 核心变化

| 维度 | 改造前 | 改造后 |
|------|--------|--------|
| **工作流** | AI 全自动判级 | AI 分类建议 + 人工确认 |
| **数据模型** | 单一研判记录 | 研判 + 地理位置 + 聚合统计 |
| **前端结构** | 单页面流程 | 双端分离设计 |
| **数据来源** | 仅用户上传 | 用户 + 公开数据导入 |
| **价值闭环** | 单点工具 | 知识库 → 决策 → 管理 |

#### 1.1 新增字段（`assessments` 表）

```python
# 地理位置
address: Mapped[str | None]
longitude: Mapped[float | None]
latitude: Mapped[float | None]
district: Mapped[str | None]  # 区
street: Mapped[str | None]    # 街道

# 分类建议（与最终分类分开）
suggested_category: Mapped[str | None]
suggested_subcategory: Mapped[str | None]

created_by_role: Mapped[str | None]
```

### 【阶段 2】后端核心服务开发（3-4 天）
**目标**：实现分类、地理编码、数据聚合三大核心服务

#### 2.1 分类服务（简化版）
**文件**：`backend/app/services/classification.py`（新建）

**核心功能**：
- 只做分类，不做等级判定
- 返回：`suggested_category`, `suggested_subcategory`, `confidence`, `reasoning`
- 使用简化 Prompt（不再需要复杂的 LangGraph 流程）

**关键代码结构**：
```python
async def classify_hazard(description: str, images: list) -> dict:
    """AI 分类建议（不判定风险等级）"""
    provider = get_provider("qwen")
    # 简化 Prompt：只分类，不判级
    result = await provider.analyze(...)
    return {"suggested_category": ..., "confidence": ...}
```

#### 2.2 地理编码服务
**文件**：`backend/app/services/geocoding.py`（新建）

**核心功能**：
- 调用高德地图 API（`https://restapi.amap.com/v3/geocode/geo`）
- 输入：地址字符串
- 输出：经纬度 + 区划信息

**配置**：在 `.env` 添加 `AMAP_API_KEY`

#### 2.3 数据聚合服务
**文件**：`backend/app/services/analytics.py`（新建）

**核心功能**：
- `get_heatmap_data()`：按区/街道聚合隐患数据
- `get_benchmark_data()`：某区 vs 全市对标分析
- `get_trend_data()`：时间序列预测（可选，简化版用统计）

**验收标准**：
- [ ] 分类 API 能返回正确的类别建议
- [ ] 地理编码服务能将地址转为经纬度
- [ ] 热力图 API 返回聚合数据（至少 10 条测试数据）

**Git 提交**：`feat(services): 实现分类、地理编码、数据聚合服务`

### 【阶段 6】前端管理者端开发（2-3 天）
**目标**：实现数据分析可视化

#### 6.1 页面结构
**新建目录**：`frontend/src/views/manager/`

**核心页面**：
- `HeatmapView.vue`：热力图（ECharts Geo）
- `BenchmarkView.vue`：对标分析（柱状图 + 表格）
- `TrendsView.vue`：趋势预测（折线图，可选）
- `ReportsView.vue`：报告生成（可选）

#### 6.2 热力图实现
**技术选型**：ECharts + 重庆市 GeoJSON

**数据流**：
1. 调用 `/api/v1/analytics/heatmap` 获取聚合数据
2. 转换为 ECharts 散点图数据格式
3. 叠加重庆地图底图
4. 支持筛选（类别、时间、区）

**关键代码**：
```javascript
import * as echarts from 'echarts'
import chongqingGeo from '@/assets/chongqing.json'

echarts.registerMap('chongqing', chongqingGeo)

chartInstance.setOption({
  geo: { map: 'chongqing', roam: true },
  visualMap: { min: 0, max: 100, inRange: { color: ['#50a3ba', '#d94e5d'] } },
  series: [{ type: 'scatter', coordinateSystem: 'geo', data: [...] }]
})
```

#### 6.3 对标分析实现
**展示内容**：
- 某区总隐患数 vs 全市平均
- 各类别隐患占比对比
- 全市排名
- 趋势对比（本月 vs 上月）

**图表**：柱状图 + 雷达图

**验收标准**：
- [ ] 热力图正常渲染，可缩放拖拽
- [ ] 筛选器生效（类别、时间）
- [ ] 对标分析显示正确的排名

## 🚀 快速启动指南

### 环境要求
- Python 3.11+
- Node.js 18+
- PostgreSQL 15+ 或 SQLite（竞赛版可用）

### 后端启动
```bash
cd backend
uv sync
cp .env.example .env  # 配置 AMAP_API_KEY
python -m alembic upgrade head
uv run app/main.py
```

### 前端启动
```bash
cd frontend
pnpm install
pnpm dev
```

### 数据导入
```bash
python scripts/import_public_data.py data/public_hazards.csv
```

## 📝 提交规范

### Commit Message 格式
```
<type>(<scope>): <subject>

type: feat | fix | docs | style | refactor | test | chore
scope: db | api | services | frontend | data
subject: 简短描述（中文）

示例：
feat(db): 添加地理位置和分类建议字段
feat(services): 实现分类、地理编码服务
feat(frontend): 实现巡查员端快速录入流程
fix: 修复热力图数据聚合 Bug
docs: 添加改造实施方案文档
```

### 分支策略
- `main`：稳定版本
- `dev`：开发分支
- `feature/*`：功能分支（阶段性开发）
- `hotfix/*`：紧急修复

**推荐流程**：
1. 每个阶段从 `dev` 创建 `feature/stage-N` 分支
2. 阶段完成后合并回 `dev`
3. 全部完成后 `dev` 合并到 `main`
