# 阶段 2：后端核心服务完成清单

## ✅ 已完成的改动

### 1. 分类服务（`backend/app/services/classification.py`）

**核心功能**：
- `classify_hazard()` - AI 分类建议（只分类，不判级）
- `recommend_regulations()` - 推荐相关法规条款
- `_fallback_rule_based_classification()` - 兜底规则分类

**分类体系**：
- 消防隐患（堵塞疏散通道、消防设施损坏、违规用火用电、易燃物品存放不当）
- 生产安全（设备故障、操作违规、防护缺失、高空作业隐患）
- 社区治理（违章建筑、环境卫生、公共设施损坏、违规占道）
- 其他

**设计特点**：
- 复用现有的 `step_analyze` 节点，避免重复实现
- 支持简化模式和兼容模式
- 模型失败时自动降级到规则分类

### 2. 地理编码服务（`backend/app/services/geocoding.py`）

**核心功能**：
- `geocode_address()` - 单个地址编码（异步）
- `batch_geocode()` - 批量地址编码（带限速）
- `reverse_geocode()` - 逆地理编码（预留接口）
- `clear_cache()` - 清空缓存

**技术实现**：
- 调用高德地图 API
- 内存缓存（避免重复调用）
- 限速处理（0.2秒/次，符合免费版 QPS）
- 异步 HTTP 请求（httpx）

**输出示例**：
```python
{
    "longitude": 106.550464,
    "latitude": 29.563761,
    "district": "渝北区",
    "street": "龙溪街道",
    "formatted_address": "重庆市渝北区龙溪街道...",
    "adcode": "500112"
}
```

### 3. 数据分析服务（`backend/app/services/analytics/`）

**核心功能**：
- `get_heatmap_data()` - 热力图数据（按区/街道聚合）
- `get_benchmark_data()` - 对标分析（某区 vs 全市）

- 内存缓存（30-60分钟过期）

## 🎯 设计说明

### 1. 为什么复用 step_analyze 而不是重新实现？

- `step_analyze` 已经集成了多模态分析、集成判断、证据检索
- 避免重复实现视觉模型调用和 Prompt 工程
- 保持一致性：简化流程和完整流程使用相同的底层模型

### 2. 为什么地理编码使用内存缓存而不是数据库？

- 地理编码结果很少变化（地址 → 坐标是稳定映射）
- 内存缓存足够（竞赛版估计 < 1000 条地址）
- 生产环境可以轻松替换为 Redis（接口一致）

### 3. 为什么热力图数据需要缓存？

- 聚合查询消耗较大（GROUP BY + JOIN）
- 热力图数据变化不频繁（30 分钟刷新一次足够）
- 缓存命中率高（同一用户短时间内多次查看）

### 4. 简化工作流如何与原有流程共存？

- 通过 `settings.simplified_workflow` 开关控制
- 兼容接口设计（签名一致）
- 可以随时切换（无需修改调用代码）
